# Shared foundation contract F1: accepted for sandbox design

Root accepts the shared contract proposal in docs/agent-work/changeo-foundations/plan.md, sections Shared contract proposal and Proposed endpoints and data shape, under S1 and subject to the required independent persistence/authorization plan review before development. Approval is a technical design decision within existing user authority; no production policy, custody or vendor approval follows.

Old contract: architecture.md assigns account/guardian/eligibility writes to identity and requires every later owner to enforce its own resource access and state. New F1 makes that boundary executable through IdentityAccess, immutable actor/subject/context requests, structured permission decisions including legal payer/evidence scope, and account snapshots. Identity owns the proposed identity-prefixed records, transactions, restrictions/revocations and auditable administration; later modules do not acquire identity repositories/entities or mutate its state.

Affected future cards: moderation/publication, profiles/listings/discovery, conversations/files, agreements/jobs, payments/credits/billing and support/integration. Every caller must combine current identity permission with its own resource membership, exact-revision moderation and applicable lifecycle/commercial/money checks. Identity authorization is never a financial operation or publication approval. Job-consent data in foundations is an identity permission boundary; actual job owner validates that the referenced job exists and that participants/mode match before it can authorize a real job action.

Approved private endpoint/data proposal remains internal to the single application. Unknown eligibility is fail-closed; public badge, provider KYC, age and verified guardian authority stay distinct. Revocation/restriction invalidates new actions immediately while controlled obligations/support/financial rights remain available. Synthetic evidence has explicit provenance/scope and cannot certify production participation. Admin password alone is insufficient; current least privilege, MFA and auditable mutations are mandatory. Secret/token confidentiality and concurrent mutation/replay boundaries must be resolved by the plan reviewer and tested by the builder/final reviewer.

S1 private loopback runtime and real-money-disabled enforcement are part of F1. Required runtime/environment checks remain real checks: no H2/compilation substitute for PostgreSQL behavior, no unavailable container/browser test reported as passed. Workspace-local tooling/ephemeral PostgreSQL investigation is permitted within current sandbox; no host configuration changes, account creation or remote service access are implied. Missing infrastructure remains an evidenced verification blocker, with useful unblocked work preserved.

Concrete risk: persisted identity/guardian/restriction state, concurrent revocation and administrator access plus contracts used across features. Separate fresh Sol/high plan reviewer must accept a viable design before the sole builder writes product code. Material shared-design changes return to root and invalidate affected acceptance as appropriate. Final feature acceptance remains exclusively the separate final reviewer.
